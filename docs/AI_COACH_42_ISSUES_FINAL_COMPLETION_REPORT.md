- 대화 코치는 **로컬 모델**(Electron Ollama 또는 사용자가 연결한 자체 AI 서버)을 씁니다. Gemini는 쓰지 않습니다(로컬 우선, Gemini 자동 fallback 없음).
- Gemini는 기준 영상 비교(`formCompare/ai.ts`) 판정에서만, 사용자가 AI 엔진을 Gemini로 고른 경우에 씁니다.
- 지시서에 적힌 `ai/useAiChat`·`aiCoach/coachService`·`aiProvider.ask`·IPC `ai:ask`는 Gemini 기반 다른 AI 기능(AI 맞춤 커리큘럼 등)의 경로입니다. 대화 코치는 이 경로를 거치지 않습니다.

- 대화 기록 → 회상·주제 이어가기·수업 추가가 직접 사용합니다. 기존처럼 일반 경로에는 최근 4턴만 모델에 전달합니다.

## 7. Intent Router 변경

추가한 의도: `UNLEARNED_TECHNIQUE_SEARCH`, `COMBO_EVALUATION`, `COUNTER_STRATEGY`, `OPPONENT_PATTERN_ANALYSIS`, `PHYSICAL_ATTRIBUTE_COMPARISON`, `PRODUCT_RECOMMENDATION`, `APP_ACTION`, `TECHNIQUE_3D_PREVIEW`, `TOPIC_CONTINUATION`, `FIGHTER_TECHNIQUE_ANALYSIS`, `PERSONAL_CONTEXT_QUERY`.

- **기존 의도 유지**: GENERAL_CONVERSATION, CONVERSATION_RECALL, PROFILE_LOOKUP, STYLE_ANALYSIS/COMPARISON/RARITY, TECHNIQUE_SEARCH, SETUP_RESEARCH(셋업·콤보 조사), MMA_STRATEGY_RESEARCH, VIDEO_SEARCH, LESSON_REQUEST/CONTINUATION, LEARNING_RECOMMENDATION, INJURY_OR_PAIN_QUESTION, EMOTIONAL_SUPPORT, SOCIAL_TRENDING.
- **기존 경로가 맡는 의도**: 기술 설명·학습 진행·숙련도·웹 조사·자세 측정 요청은 router의 기존 경로(technique / my_progress / web / pose_check)가 처리합니다.
- **분류만 바꾸지 않았습니다**: 새 의도마다 전용 실행 경로가 있고, 그 경로가 검색·모델 호출 여부를 결정합니다. 테스트가 호출 기록으로 이를 확인합니다.
- **문맥 규칙**:
  - '페인트'는 반응·속임 문맥에서만 feint로 봅니다.
  - '투'는 타격 문맥에서 단독 단어일 때만 바꿉니다('투자'는 그대로).
  - '암바처럼 아프다'는 통증입니다.
  - "내 콤보 분석해 줘"(저장된 콤보 분석)는 셋업 평가가 아닙니다. 연결 순서를 말한 경우에만 셋업 평가로 봅니다.
- **멀티 인텐트**: "토푸리아가 자주 쓰는 콤보를 찾아서 수업으로 만들어줘" → 선수 식별 → 근거 자료 분석 → 콤보(원문 인용) → 관련 영상 → 수업 제안(분석에서 확인된 기술만).

## 8. 내부 DB와 학습 기록 연동

- 미학습 판단은 결정론적 학습 모델(`learnerModel`)의 상태로 합니다. 수업·연습·복습·자세 측정 이벤트가 있으면 학습한 것으로 보고, `not_started`·`planned`는 미학습으로 봅니다. LLM은 학습 기록을 읽기만 하고 바꾸지 않습니다.
- 기술 분류 필터는 DB의 이름·분류 필드만 씁니다(DB 재구성 없음). 정규 id로 중복을 제거합니다.

## 9. 외부 검색 개선

- 새 경로는 검색 상태를 다섯 가지로 구분해 표시합니다: 실패 / 0건 / 모두 무관해 제외 / 검색 불가 / 꺼짐.
- 본문을 읽은 자료에서 질문과 관련된 문장만 **원문 인용**으로 붙이고, 인용할 문장이 없으면 요약하지 않습니다.
- 검색 결과 수를 근거 수로 세지 않습니다.
- 장비는 자료에 적힌 제품명만, 체격은 자료에 적힌 수치 문장만 씁니다. 새 유료 검색 API는 없습니다(기존 자체 검색).

## 10. 선수 분석 개선

- 기존 근거 기반 분석(`evidenceStyle`)이 실제로 실행되는지 확인했습니다. 이 분석은 선수가 그 동작을 했다고 쓴 원문 문장만 쓰고, 사용·참고 자료를 구분하며, 확인되지 않은 항목은 "확인 못함"으로 둡니다.
- 의도 목록에 `FIGHTER_TECHNIQUE_ANALYSIS`를 표시하고, 수업 생성 요청을 연결했습니다.
- **한계**: 경기 영상 자체를 분석하지 않으므로 영상 타임스탬프는 제공하지 않습니다(보고서에 명시).

## 11. 셋업 및 콤보 분석 개선

- **셋업 판정**: 앞 동작이 끌어내는 상대 반응이 원리 표에 있을 때만 셋업이라고 부릅니다(예: 펀치 → 하체 태클 = 레벨 체인지). 반응이 정해지지 않은 타격 연결은 "단순 연결/콤보"로 판정합니다(테스트로 확인).
- **사실과 판단 분리**: 기록(사실) / 앱의 판단(원리) / AI 해석(추론)을 섹션으로 나눕니다.
- **중복 제거**: "이거 말고"는 이전 답변의 항목 줄을 제외합니다.

## 12. 수업 시스템 개선

- 수업에 대화 전체의 관련 출처를 전달합니다(K32).
- 수업 중 이름으로 요청한 기술을 제안합니다(K34).
- 수업 화면 밖에서도 진행 중인 수업에 추가합니다(B11).
- 수업 id·단계·위치·진행 기록은 동의 전후 모두 유지됩니다(실제 `sessionStore`로 검증).
- 수업 제안은 실행 경로 의도에서는 자동으로 붙이지 않습니다(학습 가치가 있을 때만 하는 기존 규칙 유지).

## 16. 3D 자세 측정 개선

- Phase 2–6 설계를 유지했습니다: 사용자가 각도 선택 → 1회 재생·실제 녹화 → 기준 영상 등록 → 각도 안내 → 사용자가 직접 촬영 → 기존 비교 엔진·점수. 앱은 시점을 바꾸거나 보정하지 않습니다.
- **이번에 찾아 고친 결함 (Android)**: Android System WebView에서 3D 녹화가 매번 "인코더가 프레임을 받지 못했습니다"로 실패했습니다.
  - 원인(측정): 이 WebView의 MediaRecorder는 100ms 데이터 간격을 지키지 않아, 첫 데이터가 3.4–6.2초 뒤에 오거나 8초 안에 오지 않았습니다.
  - 수정: 예열 중 250ms마다 `requestData()`로 버퍼를 내보내게 했습니다. 그러면 VP8은 1.3초, VP9는 2.7–4.4초에 데이터가 나왔습니다. 상한은 10초로 늘렸고, 파일 길이 검증은 실제 대기 시간을 계속 씁니다.
  - 수정 후 Android 녹화·등록 성공(33KB, 2.3초 파일). Electron 회귀 없음(20/20, 10/10).
- **방향 판정**: Phase 6의 일치·불일치 가능성·확인 불가 판정과 "확인 불가면 신뢰도 높음 금지" 규칙을 유지합니다. 로컬 방향 추정 정확도(3D 녹화 4각도 중 1개 정답)는 개선하지 않았고, 개선했다고 주장하지 않습니다(검증 데이터 없음).
- **체형 차이 조사(측정)**: 측면 영상에서 3D 마네킹과 사람 캐릭터(Blender)의 팔다리 길이 비율(몸통 대비 중앙값)은 다음과 같습니다.
  - 위팔 0.557 vs 0.556, 아래팔 0.373 vs 0.356, 허벅지 0.788 vs 0.785, 정강이 0.803 vs 0.784 — 차이 5% 이내
  - 어깨 너비는 0.396 vs 0.082로 크게 다름 → 몸통이 카메라를 향한 각도(스탠스 각도) 차이
  - 따라서 Phase 6에서 보조 신호가 "부분 일치"로 낮춘 차이는 팔다리 체형보다 스탠스 각도 차이에서 왔을 가능성이 큽니다. 표본이 영상 2개뿐이라 확정하지 않았고, 점수 기준은 바꾸지 않았습니다.
