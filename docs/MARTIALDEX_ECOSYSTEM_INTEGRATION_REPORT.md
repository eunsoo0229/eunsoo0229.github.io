## 1. 실제 구현한 기능

### A. 체육관 운영·코칭 대시보드 (`/gym/admin/:gymId`, `/gym/admin/:gymId/member/:userId`, `/gym`)
- 탭: 대시보드 · 회원 · 가입 신청 · 과제·피드백 · 공지 · 수업(기존 클래스·라이브 그대로).
- 대시보드 지표: 전체/활성 회원(14일), 출석률(가입 이후 열린 수업만 분모), 수업 참여(완료)율, 기술 학습 완료율(숙련/학습 — 진도 공유 회원 기준), 주별 출석, 장기 미접속, 회원별 성장. 데이터가 없으면 0% 가 아니라 "데이터 없음"과 이유.
- 가입 승인제(관장이 켜고 끔), 신청 승인/거절, 역할 변경(관장만), 회원 내보내기.
- 회원 상세: 출석 이력, 공유된 진도(숙련도 분포·기술별 상태·자세 점수 처음→최근·측정 신뢰도·훈련량), 과제/기술 권장/피드백/AI 분석 검토 의견 작성·수정, 개별 메시지(기존 DM).
- 학생 화면: 공지, 내 과제(완료·메모), **진도 공유 동의**(무엇이 공유되고 무엇이 공유되지 않는지 명시, 동의 체크 전 버튼 비활성, 언제든 중지).

### B. 훈련 성과 검증 (`/progress`)
- 기존 자세 측정 기록만 사용. 기술 × 측정 방식(관절 지표 / 기준 영상 / 3D 기준)별로 묶고 **방식이 다르면 섞지 않음**.
- 처음 → 최근 점수, 항목별 변화, 개선된 항목, 개선되지 않은 항목, 반복 약점(절반 이상 60점 미만), 반복 측정 일관성(최근 5회 표준편차), 신뢰도(측정 횟수·저신뢰 측정 비율·편차) + 사유.
- 기간 요약(30일/90일/1년): 기간 안 2회 이상 측정한 기술만 변화 계산.
- 영상 비교: 기기의 두 영상을 골라 비교 구간 시작점·길이 지정, 동시 재생(0.25/0.5/1x), 촬영 각도 표기와 **각도 불일치 경고**(영상 변환 없음). 영상은 저장·업로드하지 않음.

### C. 개인 훈련 프로그램 (`/program`)
- 결정론 엔진(`trainingProgram/engine.ts`): 체육관 과제 → 약점(기존 약점 엔진 순위) → 복습 예정 → 새 기술(즐겨찾기 우선, 쉬운 난이도 우선) → 내 콤보 순으로 배치. 같은 입력 = 같은 계획.
- 조정: 지난주 완료율 <50% 하루 분량 −1, ≥90% 새 기술 +1, 못한 약점·복습은 다음 주로 이월, 최근 7일 과다·3일 연속 훈련 시 훈련일 −1(회복).
- 사용자 수정: 완료 체크, 다른 요일로 옮기기, 빼기, 기술 추가, 휴식일 전환, 설정(주당 일수·시간·집중 종목·새 기술 수·고정 휴식 요일), 이번 주 목표(기존 목표 저장소와 같은 기록).
- "훈련 기록에 남기기" → 기존 `trainingHistory` 에 1건(다시 누르면 이전 건을 지우고 새로 남김 — 중복 없음) → 숙련도·복습 주기에 기존 경로로 반영.
- AI 코치 통합: 기존 `userCoachContext`(훈련 루틴 주제)에 이번 주 계획·완료율 한 줄 추가. 새 코치를 만들지 않음, AI 호출 없음.

### D. 숏폼·게시물 기술 평가
- 기존 `PostComposer`(게시물·숏폼 공용)에 "기술 평가 받기": 종목, 기술 이름 + 기술 DB 검색 연결, 종목별 기본 항목 템플릿(복싱/킥복싱·무에타이/주짓수/레슬링/유도·삼보/MMA…) 중 선택(최대 8), 투표 기간, 결과 공개/나만 보기.
- 투표: 항목별 0~100% 슬라이더(움직인 항목만 제출), 항목별 피드백, 개선 의견, "댓글로도 남기기"(점수와 의견 분리).
- 결과: 전체 평균 막대그래프(내 점수 세로선), 응답 수·점수 분포(5구간), 참여자 수, 신뢰도 배지(1~2명 표본 부족 / <10 낮음 / <30 보통 / 충분 — 충분해도 "공식 인증 아님"), 평가자 그룹별 평균(미검증/초급/중급/숙련/검증된 지도자 — **3명 미만 그룹은 숨김**), **같은 체육관 회원 제외 평균**, 내 점수와 평균 차이.
- 피드백 목록(익명), 작성자 "유용함" 표시, 피드백·투표 신고, 작성자의 결과 공개 전환·평가 종료(종료 후 재개 불가, 결과 보존).
- 연결: 피드 카드 미리보기, 숏폼 레일 "평가" 버튼 + 미리보기, 게시물 상세 전체 패널, 프로필 "받은 기술 평가" 요약, `/evaluations`(받은 평가·참여한 평가·종목별).
- 좋아요(`community_post_likes`)와 완전히 별개.

### E. 장비 중고거래 (`/gear`, `/gear/new`, `/gear/:id`, `/gear/:id/edit`, `/gear/mine`)
- 10개 카테고리, 종목, 브랜드, 사이즈(카테고리별 입력 안내), 사용 기간, 상태 5단계(모든 화면이 같은 기준 문구), 가격, 설명, 이미지 8장, 지역, 택배/직거래.
- 검색·필터: 검색어, 종목, 종류, 브랜드, 사이즈, 가격 범위, 상태, 지역, 판매완료 포함, 최신/가격순.
- 거래: 판매자 프로필·평점, 찜, **문의 = 기존 DM**(상품 카드 첨부), 상태(판매 중/예약 중/판매 완료/숨김), 판매 완료 시 문의한 사람 중 구매자 지정, 거래 후기(쌍방 1회), 신고, 판매자 차단(기존 차단 재사용), 내 판매·관심·구매·받은 후기.
- 안전 안내(선입금·외부 링크·개인정보·위생용품·미성년 보호자 동반). 결제·에스크로 없음.

### F. 체육관 검색·가격 비교·제휴 할인 (`/gyms`, `/gyms/:id`, `/gyms/compare`, `/gyms/deals`, `/gyms/coupons`, `/gyms/manage`)
- 검색(이름·소개·종목), 필터(11개 종목, 지역, 제휴만, 체험 가능, 자유 연습, 월 회비 상한), 정렬, 최대 4곳 비교.
- 상세: 주소·지도 링크(OpenStreetMap), 연락처·홈페이지·SNS, 운영 시간, 시설, 지도자, 시간표, 가격표, 후기("실제 회원" 표시는 서버 판정), 등록 문의(DM).
- 가격 비교: 월/3/6/12개월, 입회비, 등록비, 장비, 주당 횟수, 1회 시간, 자유 연습, 여러 종목, 체험(가격). 첫 1년 총비용·1회당 비용은 **모든 구성 요소를 알 때만** 계산. 모르는 값은 "정보 없음". 최종 확인일·플랫폼 검증 여부 표시.
- 제휴 할인: 할인 전 가격 취소선 + 제휴 가격. 할인가는 **플랫폼이 검증한 원래 가격으로 서버가 계산**, 미검증이면 할인가를 표시하지 않고 쿠폰도 발급되지 않음. "화면 예시"(150,000원 → 120,000원)는 별도 상자에 "실제 가격이 아님"으로 분리.
- 쿠폰: 발급(1인 1회, 인원 제한, 신규 회원 대상 확인), 체육관의 사용 처리 → 사용자 화면 "사용 완료 · 등록 확인", 취소, 만료 표시.
- 체육관 관리자: 등록·수정(대표 이미지 업로드), 가격 관리(변경 시 검증 자동 해제 경고), 제휴 신청/재신청(수익 모델 안내), 할인 등록·진행·중지·종료, 쿠폰 사용 처리·현황, 유입 통계(문의·발급·사용·전환율·월별).

### 공통: 플랫폼 관리자·자격 검증 (`/admin/platform`, `/verification`)
- 플랫폼 관리자 콘솔: 체육관 등록 승인/반려/중단 + 가격 검증, 제휴 계약 활성화(계약 번호·시작일 필수)/거절/종료, 자격 신청 승인/거절, 신고 처리(상품 내리기, 부정 투표 무효화, 처리 완료).

## 2. 기존 기능과 연결한 부분
- 계정·인증: 기존 Supabase 인증·`profiles` 그대로. 새 역할 테이블 없이 `gym_members.role`(지도자/학생), `gyms.owner_user_id`(체육관 관리자), `platform_admins`(신규, SQL 로만 부여) 조합.
- 게시물·숏폼: `community_posts` 1:1 로 평가를 붙임(새 피드 없음). `PostComposer`·`PostCard`·`PostDetail`·`Shorts`·`UserProfile` 에 통합. 공개범위·차단은 0045 규칙을 그대로 따름.
- DM: 장비 문의·체육관 등록 문의·회원 개별 메시지 모두 기존 `start_conversation`/`messages`. DM 첨부에 '장비 상품' 종류 추가.
- 차단·신고: 기존 `user_blocks`·`is_blocked_between`·`user_reports`(대상 종류만 추가), 플랫폼 관리자 신고함.
- 체육관: 기존 `gyms`/`gym_members`/수업 세션/출석 테이블에서 출석·참여를 계산(중복 저장 없음). 공개 체육관 목록은 기존 체육관에 선택적으로 연결.
- 학습·훈련: 기존 숙련도(`computeAllSkillProgress`), 약점 엔진, 자세 측정 기록, 훈련 기록, 즐겨찾기, 콤보, 목표 저장소를 읽기만 함. 프로그램 완료는 기존 훈련 기록에 저장.
- AI 코치: 기존 컨텍스트에 프로그램 요약 한 줄. 새 AI 호출·공급자 변경 없음.
- 내비게이션: 상단 기본 메뉴에 체육관·마켓·커뮤니티 추가, 메뉴 그룹에 마켓 그룹 신설, 훈련·커뮤니티·체육관·계정 그룹에 새 항목. 기존 메뉴 삭제 없음.

## 6. RLS 및 권한 정책
- 모든 새 테이블 RLS 켬. 다른 사람 데이터를 읽는 정책은 필요한 범위만:
  - 투표 행은 본인만 읽음, 쓰기 권한 자체가 없음(RPC 전용). 집계는 익명 숫자만 반환.
  - 진도 요약은 본인 + 그 체육관 지도자만 읽고, 쓰기는 본인만(지도자도 수정 불가). 체육관 회원 FK 로 비회원은 행을 못 만듦.
  - 과제는 대상 회원 + 지도자. 회원은 상태·메모만 바꿀 수 있음(트리거).
  - 공지는 회원만.
  - 체육관 목록은 승인된 것만 공개(등록자·관리자 예외). 상태·검토 열은 플랫폼 검토로만 바뀜(트리거).
  - 제휴 계약 조건(수수료·월 구독료·계약 번호)은 등록자·플랫폼 관리자만. 공개는 "유효한 제휴인가"만.
  - 쿠폰은 쓰기 정책이 없음(발급·사용·취소 RPC). 사용 처리는 그 체육관 등록자만.
  - 장비: 찜 수·관리 상태는 서버만 변경, 구매자는 실제 문의한 사람만 지정, 차단 관계면 상품이 안 보임.
  - 이미지 버킷은 본인 폴더에만 쓰기 + 서버측 형식(이미지)·크기(8MB) 제한.
- 플랫폼 관리자: `platform_admins` 에 SQL 로만 추가(클라이언트 INSERT 정책 없음). 우회 설정값이 있어도 관리자 확인을 다시 함.
- **기존 빈틈 수정(0022/0025)**: 가입 코드만 알면 누구나 스스로 `instructor` 로 가입할 수 있었고, 학생이 자기 역할을 바꿀 수 있었음 → 지도자는 체육관 관리자만, 역할 변경은 관리자만(트리거). 기존 행은 건드리지 않음.

## 7. 기술 투표 집계 방식
- 1인 1표: `(post_id, voter_id)` 기본키. 다시 투표하면 같은 행을 덮어쓰고 `revision`+1 → 최신 점수만 집계.
- 서버 검증(`cast_technique_vote`): 로그인, 게시물 공개범위, 투표 기간, 자기 투표 금지(기본), 차단, 정수 0~100, 설정된 항목만, 피드백 300자, 속도 제한(분당 20·일 300), 무효 처리된 투표는 되살릴 수 없음.
- 통계(`get_technique_evaluation_stats`)는 호출할 때마다 유효 투표에서 계산(저장된 집계 열 없음 → 요청 조작으로 평균·참여자 수를 바꿀 수 없음): 항목별 응답 수·평균·5구간 분포, 그룹별 평균(검증 자격 기준, 3명 미만 숨김), 같은 체육관 회원 제외 평균, 결과 비공개면 작성자 외에는 참여자 수만.
- 철회(`withdrawn`)·무효(`invalidated`) 투표는 통계 제외. 종료 후 재개 불가, 결과 보존.
