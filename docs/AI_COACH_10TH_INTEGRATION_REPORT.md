## 4. 새로 연결한 데이터: 구현 완료, 자동화 테스트 통과

새 모듈은 `src/lib/coachContext/coachData.ts`입니다.

- 각 저장소의 공개 API로만 읽고, 아무것도 쓰지 않습니다.
- 데이터마다 공통 메타정보 `DataMeta`를 붙입니다:
  - `source`(출처), `userId`(소유 계정), `createdAt`/`updatedAt`(생성·수정 시각)
  - `freshness`: 최근 / 몇 달 전 / 오래된 기록 / 날짜 없음
  - `syncStatus`: 이 기기에만 있음 / 계정 동기화 대상 / 동기화 상태 기록 없음
  - `confidence`: 사용자 입력 / 앱 계산 / AI가 만든 내용을 사용자가 저장
- 콤보와 전술은 `userId`가 비어 있으면 "이 기기에만 있음(계정에 아직 안 올라감)"으로 표시합니다.

데이터별로 연결한 내용:

| 데이터 | 연결 방식 |
|---|---|
| 콤보 | 단계별 기술 존재 여부와 숙련도, 기술 연결 기록에 있는 연결과 없는 연결, 마지막 기술 다음에 이어지는 실제 기술 |
| 전술 | 상황 문장에서 읽은 거리, 숙련 기록이 부족한 단계, 다른 전술·콤보와 순서가 같은지, 이전에 받은 AI 피드백 |
| 나만의 기술 | 공식 기술과 구분해 표시, 이름이 비슷한 공식 기술, 연결 가능한 기술. 코치가 수정·삭제하지 않습니다. |
| 즐겨찾기 | "관심 표시일 뿐 숙련도 아님"을 명시하고, 학습 기록이 없는 즐겨찾기부터 학습 경로를 제안 |
| 스파링 | 원문 기록, 기록에서 센 집계(성공률이 아니라 "사용했다고 기록한 횟수"), 앱의 판단을 나눠 표시. 승패·성공률은 만들지 않습니다. |
| 식사 | 기록이 있는 날만 계산하고 기록 없는 날은 추측하지 않습니다. AI·사진 추정치는 표시합니다. 극단적인 제한이나 무리한 감량은 권하지 않는다는 안전 문구를 붙입니다(성장기 고려). |
| 과거 대화 → 장기 학습 메모리 | 자주 물어본 기술, 반복한 질문, 어렵다고 말한 내용, 요청한 설명 방식, 끝낸 수업, 수업에서 부족했던 개념을 앱이 정리합니다. 따로 저장하지 않고 매번 원본에서 계산하므로, 원본은 그대로이고 사용자가 지운 대화는 메모리에도 반영되지 않습니다. |

## 5. 데이터별 실제 AI 활용 방법

`src/lib/coachContext/coachAnalysis.ts`가 질문을 다음 분석으로 연결합니다. 모두 코드가 작성하는 결정론적 답변입니다.

| 질문 예 | 분석 | 읽는 데이터 |
|---|---|---|
| 내가 저장한 콤보 분석해 줘 | 콤보 분석 | 콤보, 숙련도, 기술 연결 기록 |
| 내 숙련도 기반으로 새 콤보 추천 | 콤보 추천 | MARTIALDEX에 기록된 콤보(기술 DB·공유 콤보)만 사용. 이미 저장한 콤보는 제외하고, 숙련 기술이 많은 콤보부터 보여 줍니다. |
| 내 전술 장단점 | 전술 분석 + 코치 해석 | 전술, 콤보, 숙련도 |
| 내가 만든 기술 연결 | 나만의 기술 | 나만의 기술, 기술 연결 기록 |
| 즐겨찾기로 학습 계획 | 즐겨찾기 | 즐겨찾기, 숙련도 |
| 최근 스파링 기록 분석 | 스파링 분석 + 코치 해석 | 스파링 기록, 영상 분석, 목표, 숙련도 |
| 반복적으로 어려워하는 상황 | 반복 어려움 | 스파링 "개선할 점", 코치 대화, 수업 약점, 개선 필요 기술 |
| 지난 기록 기반 다음 훈련 | 다음 훈련 | 최근 2주 기록, 개선 필요·학습 중 기술, 목표 기술, 루틴 요일. 추천은 훈련 기록에 저장하지 않습니다. |
| 과거 대화 참고해 학습 상태 | 학습 상태 | 장기 학습 메모리, 숙련도 |
| 내 영양 기록 참고 | 영양 | 영양 프로필, 식사 기록 |
| 내 파이팅 스타일 | 스타일 + 코치 해석 | 프로필 스타일, 스타일 분석, 영상 분석, 숙련 기술 |
| 이번 주 목표에 맞는 수업 | 수업 계획 | 저장된 목표 문장에 나오는 기술로 기존 플래너가 수업을 만듭니다(플래너 규칙은 그대로). |
| 내 콤보와 전술을 보고 방향 알려줘 | 종합 질문 | 여러 데이터를 묻는 질문은 모델이 전체 컨텍스트(콤보·전술 섹션 포함)로 답합니다. |

"코치 해석"(전술·스파링·스타일)은 이렇게 만듭니다:
- 로컬 모델은 코드가 정리한 기록 블록만 받고, 기록에 없는 승패·성공률·수치를 만들지 말라는 지시를 받습니다.
- 모델의 문장은 기록과 대조해 반대되는 문장을 지우고, 기술명 표기를 정리합니다.
- 모델을 쓸 수 없으면 해석 없이 기록과 앱의 판단만 보여 줍니다.

모든 답변에는 읽은 저장소 목록(personalData)이 붙습니다. AI가 사용자 데이터를 바꾸는 경로는 없습니다(테스트로 확인).

## 6. UserCoachContext 변경 내용

- 수업하기는 9차와 같은 공통 컨텍스트를 그대로 쓰므로, 새 데이터도 같은 방식으로 받습니다.

## 12. 데이터 보존과 계정 전환 검증 결과

**구현 완료, 자동화 테스트 통과** (`src/lib/auth/deviceAccountGuard.ts`)
- **기존:** 다른 계정으로 로그인하면 `martialdex:*` 데이터를 모두 지웠습니다. 그래서 동기화되지 않은 기록이 없어졌습니다.
- **변경:**
  - 이전 계정의 데이터를 그 계정 전용 보관소 `mdx:account-stash:<userId>`로 옮깁니다. `martialdex:` 접두사 밖이라 백업·동기화 대상이 아니고, 새 계정에게 보이지 않습니다.
  - 그 계정으로 다시 로그인하면, 동기화가 시작되기 전에 복원해서 미동기화 기록이 이어서 업로드됩니다.
  - 지운 다음 보관하는 순서라서 비운 공간을 보관에 씁니다.
  - 보관에 실패하면(저장 공간 부족) 실패 표시를 남깁니다(`accountStashFailures()`).
- **테스트 시나리오:** A 기록 작성 → B로 전환 → A 다시 로그인
  - B에게 A 기록이 안 보이고, B의 AI 컨텍스트에도 없음
  - A 기록은 A 보관소에 있고, A로 돌아오면 복원되며 중복 없음
  - B 기록은 B 보관소에 보존, 같은 계정 재로그인은 아무것도 지우지 않음, 테마 설정 유지
- **미검증:**
  - 실제 Supabase 계정으로 하는 전환 테스트(운영 가입 가드로 실행하지 않음)
  - 네트워크 복구, 동기화 재시도, 앱 재시작 상황(실기기·실계정 필요)
- **남은 위험:**
  - 다른 기기에서 지운 항목이 오래된 보관본 복원으로 되살아날 수 있습니다(삭제 표시가 보관본에 없는 경우).
  - 보관에 실패했을 때 설정 화면 경고 UI는 아직 없습니다.

## 13. 한국어 품질과 검색 출처 개선 결과

**기술명 (`src/lib/selfAi/terminology.ts`): 구현 완료, 자동화 테스트 통과, Mac 개발 환경 검증**
- 공식 이름은 MARTIALDEX 데이터에서만 가져옵니다(`koreanName`, `dataKoreanNames`). 추측하지 않습니다.
- 그 표기 목록을 프롬프트에 넣습니다.
- 답변 후처리:
  - 영어 기술명은 처음 한 번 "잽(Jab)", 이후 "잽"으로 바꿉니다.
  - 소리가 같은 다른 철자를 바로잡습니다(쨉→잽, 키무라→기무라).
  - 받침만 다른 오기를 바로잡습니다(잭→잽). 1음절 이름은 조사나 붙은 말이 있을 때만 고치고, 흔한 단어(잘·잔·한 …)는 제외합니다.
- 규칙으로 알 수 없는 오기(예: "잉크", 모음까지 다른 "잣")는 바꾸지 않습니다.
- 실측: 3B 답변의 "잭"과 영어 "Jab", "Hook", "Slip"이 정리됐습니다. "Cross"처럼 데이터에 한국어 이름이 없는 기술은 영어로 남습니다.

**출처: 구현 완료, 자동화 테스트 통과**
- 검색 결과마다 앱이 `sourceId`(정규화한 URL의 해시)와 검색 시각(`fetchedAt`)을 붙입니다.
- 근거 대조의 각 판정은 sourceId로 실제 자료를 가리킵니다. [n]은 이 답변 안에서의 순서일 뿐입니다.
- 출처 목록 위에 "이번 질문에서 새로 검색 — HH:MM" 또는 "이전 검색 결과 — HH:MM 검색, 서버 상태"를 표시합니다.
- 검색 결과가 없으면 출처를 표시하지 않습니다.

**의미 왜곡: 구현 완료, 자동화 테스트 통과**
- 8차의 2% 왜곡 회귀 테스트를 유지했습니다.
- 부정/긍정 반전 검사를 추가했습니다("도움이 된다" ↔ "도움이 되지 않는다").
- 답변마다 확인된 문장 / 확인되지 않은 문장 / 지운 문장 수를 표시합니다.
- **한계:** 단어·수치 비교라서 의미를 완전히 검증하지 못합니다. 그래서 확인되지 않은 문장은 "원문 확인 필요"로 표시합니다.

## 16. 발견한 문제와 미해결 항목

1. **원본에 합치기:** 10차 결과는 복제본에만 있습니다. 원본에 합칠지는 사용자 결정이 필요합니다.
2. **3B 모델 속도:** 종합 질문은 프롬프트가 길어 CPU에서 109~370초 걸렸습니다. 컨텍스트 길이를 줄이거나 작은 질문별 요약이 필요합니다.
3. **3B 한국어 품질:** 규칙으로 알 수 없는 오기("잉크", "잣")는 남습니다. 데이터에 한국어 이름이 없는 기술(Cross 등)은 영어로 표시됩니다.
4. **의미 검증의 한계:** 미묘한 의미 왜곡은 놓칠 수 있고, 확인되지 않은 문장으로만 표시됩니다.
5. **계정 전환의 남은 위험:** 오래된 보관본 복원과 삭제 동기화가 충돌할 수 있고, 보관 실패 경고 UI가 없습니다. 실계정 테스트는 미검증입니다.
6. **배포 구조:** 패키징 앱은 Python·Ollama를 사용자가 직접 설치해야 합니다.
7. **운영 QA 계정 4개와 Gemini 사용량은 확인하지 못했습니다.** 운영 DB, Supabase 대시보드, Google AI Studio에 접근하지 않았습니다. 운영 가입 가드는 그대로 유지했습니다.
8. **Electron 다운로드:** 패키징 빌드 때 electron-builder가 Electron 압축 파일(약 100MB)을 다시 내려받았습니다. 큰 다운로드는 먼저 알려야 했는데 그러지 못했습니다.
