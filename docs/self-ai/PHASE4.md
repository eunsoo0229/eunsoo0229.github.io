# 자체 AI 4차 — 개인화 코치 · 검색/선수 분석 · 수업 엔진 · 자세 측정 통합

브랜치 `ai/self-hosted-overhaul` (개발용 복제본만). 원본 저장소 미수정. 조사 결과: [PHASE4_AUDIT.md](PHASE4_AUDIT.md).

## 1. 기존 구조 조사 결과 (요약)
- 자체 AI가 두 갈래였음: 3차까지 개선한 `selfAi/coachAgent`(대화·수업) / 헤더 "AI에게 묻기"의 이전 경로(`ai/martialdexAsk.ts` = 데이터 답변 + **Tavily**).
- "레슬링 솔로 드릴 훈련을 하고 싶어" 실패 원인: 훈련 의도 → 수업 생성 경로가 없어 모델이 학습자 기록(여러 무술 연습 이력)을 보고 기술을 나열.
- 토푸리아 실패 원인: 성만 입력하면 위키백과 이름 확인 실패 → 한국어 이름으로 검색 → 무관한 결과, 재검색·관련성 재평가 없음.
- 숙련도(5단계)는 자세 측정 기록이 있으면 자세 점수만으로 결정 → 학습 숙련도와 자세 점수가 섞여 있음.
- 자세 측정: 로컬 `poseAnalysis`(18개 기술, MediaPipe+규칙) / `formCompare`(기준 영상 비교, 판정은 Gemini). 측정 불가 지표(관절 미감지)의 임시 50점이 종합 점수 평균에 들어가던 문제 발견.

## 2. 수정·추가 파일과 기능

### Phase 4-A — 검색·선수 분석·훈련 의도
- `electron/selfSearch/entity.cjs` — 성·별칭("토푸리아", "맥그리거", "존스")을 검색으로 찾은 전체 이름(한국어 위키백과·나무위키 문서 제목)으로 확인, 격투기 선수 문서인지 확인, 여러 명이면 고르지 않고 후보를 돌려줌. 위키백과 `/w/` API는 robots.txt가 막아 쓰지 않음.
- `src/lib/fighterStyle/evidenceStyle.ts` — 질문 주제(타격·복싱·셋업·콤비네이션·카운터·거리·그래플링)로 검색어, 선수 이름이 없는 결과 제외, 같은 기사 사본 1개로, 관련 본문 3곳 미만이면 다른 검색어로 최대 3회 재검색, 실패 원인 구분(접근 실패·본문 추출 실패·무관·이름 없음·기술 없음).
- `src/lib/fighterStyle/ruleExtract.ts` — 상대 반응을 이용한 셋업("when opponents …, he …"), 합성어("cross-weight") 제외, 부정문("doesn't rely on volume")·훈련 일정 문장 제외. `actor.ts` — 선수가 소유격으로만 나오는 문장의 "he"는 다른 사람.
- `src/lib/selfAi/fighterReport.ts` — 이름 확인 경로, 검색 과정(회차별 결과·관련·본문 수, 사용 못한 이유). `coachAgent.ts` — 동명이인이면 검색하지 않고 전체 이름을 물어봄.
- `src/lib/selfAi/router.ts` — 의도 추가: 훈련 수업(솔로·파트너·종목·복습·약점), 내 학습 상태(8종), 수업 이어하기, 자세 확인, "더 잘하려면".
- `src/lib/selfAi/trainingPlanner.ts` (신규) — 훈련 요청 → **그 무술 기록만**으로 수업 계획: 복습(배운 기술)·보강(부족)·준비(다음 기술)·기초(기록 없을 때). 솔로 드릴은 혼자 가능한 동작만(레슬링·주짓수: 기존 솔로 드릴 구령 목록과 기본 움직임 분류, 타격: 자세·풋워크·공격·회피), 파트너 드릴은 그 반대 + "파트너 1명 필요". 만들 수 없으면 이유와 대안. 수업 시작 버튼 + 레슬링·주짓수는 기존 솔로 드릴 화면 버튼.
- `src/lib/ai/martialdexAsk.ts` — 헤더 "AI에게 묻기"(MARTIALDEX)를 같은 자체 AI 코치(`runCoachTurn`)로. **Tavily 경로 제거**(자체 검색만).

### Phase 4-B — 개인화 데이터
- `src/lib/personalCoach/learnerModel.ts` (신규, 읽기 전용) — 학습 상태 7종(미학습·학습 예정·학습 중·학습 완료·복습 필요·숙련도 부족·숙련도 향상 중), **학습 숙련도**(수업·연습·복습 기록만, 하루 1회·체감, 수업 1회 ≤ 30, 3일 ≈ 66, 30일 이상 쉬면 표시값 감소) — **자세 점수는 별도 값**(카메라 측정만). 같은 수업 기록이 다시 저장돼도 한 번만 반영(수업 기록 id 기준), 수업에 연결된 연습 기록은 이중 집계 안 함.
- `learnerStore.ts` — 이 기기의 현재 계정 기록만 읽음(다른 계정 로그인 시 기존 `deviceAccountGuard`가 로컬 데이터 삭제, 클라우드는 계정별 RLS). AI는 기록을 쓰지 않음(테스트로 확인).
- `personalAnswers.ts` — 배운 기술·안 배운 기술·가장 부족한 기술(학습 숙련도와 자세 점수 따로)·향상·복습·배운 기술로 만들 수 있는 콤보(내 콤보·공유·DB, 미학습 단계 표시)·다음 학습(선행 기술·연결·예정·난이도)·실력 분석(시나리오 A). 기록이 없으면 "기록이 없습니다".
- `improveAnswer.ts` — "이 기술을 더 잘하려면?" (수업 중 포함): 내 학습 상태·자세 점수·지난 수업에서 확인 안 된 포인트·안 배운 선행 기술·솔로 드릴·내 콤보.
- 수업 완료 반영: 기존 수업 종료 처리(`saveLessonLog`·연습 기록)를 그대로 사용 — 학습 숙련도·복습 예정·콤보 학습 상태는 그 기록에서 계산. 콤보·셋업 숙련도는 연결 동작을 평가할 근거 데이터가 없어 **산출하지 않음**(구성 기술의 학습 여부만 표시).

### Phase 4-C — 자세 측정
- `src/lib/poseAnalysis/analyzeTechnique.ts`, `metrics.ts`, `types.ts`, `PoseAnalysisModal.tsx` — 관절을 못 찾은 지표는 `measured: false`로 표시하고 종합 점수에서 제외, 측정된 지표가 2개 미만이면 점수 없음(기존 카메라 측정에도 적용 — 측정 불가를 50점으로 평균하던 문제 수정).
- `src/lib/poseCoach/poseCoach.ts` (신규) — 측정 가능 여부(설정 있는 18개)와 같은 무술의 대안, 촬영 안내(설정의 필요 관절·지표에서: 화면 범위·높이·거리·위치·동작, 방향은 엔진이 비교하지 않음을 명시), 단일 기술 기준 영상 선택(제목·설명 기준: 기술 이름 포함, 콤보·하이라이트·모음 제외, 앱 재생 가능, 10분 미만), 영상 프레임 평가(기존 엔진, 사람 없음·동작 없음·너무 짧음·몸 잘림 → 재촬영, 신뢰도, 측정 불가 항목, 다음 훈련), 수업 중 제안 조건.
- `src/pages/PoseCheck.tsx` (신규, `/pose-check/:id`) — 촬영 안내·기준 영상 카드·"카메라로 측정"(기존 PoseAnalysisModal)·"영상 파일로 측정"(formCompare의 로컬 프레임 추출 → 같은 엔진, 파일은 기기에서만 처리·저장 안 함). 점수가 나온 경우에만 기존 자세 기록에 저장.
- `coachAgent.ts` — 자세 확인 요청: 측정 불가 기술(싱글렉 등)·계열은 측정하지 않고 안내, 기준 영상이 없으면 시작하지 않음, 있으면 안내 + 측정 시작 버튼.
- `CurriculumCoachSession.tsx` — 측정 가능한 기술의 실습이 끝나면 "자세 측정하기 / 나중에 하기" 1회 제안. 거절은 이 수업 동안만 기억(sessionStorage), 수업 상태·숙련도·자세 점수 불변.

## 8. 남은 문제
- 로컬 자세 측정은 18개 기술뿐(싱글렉 등 그래플링 기술 대부분 미지원). 기준 영상은 보기용이며 점수와 비교하지 않음(YouTube 영상 프레임은 앱에서 읽을 수 없음). 촬영 방향은 엔진이 비교하지 않음.
- 학습 숙련도 공식은 규칙 기반 첫 버전 — 실제 사용 데이터로 조정 필요. 기존 5단계 숙련도 화면은 그대로(자세 점수와 섞인 기존 정의 유지).
- 솔로 가능 분류는 분류 이름·기존 솔로 목록 기반 — 유도·삼보는 기본 움직임 외 자료 부족.
- 선수 분석은 규칙 기반이라 검색 결과에 따라 품질이 달라짐(일부 페이지는 robots·차단으로 본문을 못 읽음).
- 모델 생성 속도(CPU) 그대로.
